What makes Codebay different?

Not another wrapper around an agent SDK — the real thing, properly sandboxed.

Real isolation, not worktrees

Every instance is its own Docker container — no shared worktrees, no port collisions, no accidentally killing your dev server, and nothing left behind to clean up when you're done.

Local or fully remote

Run it against Docker Desktop or Colima on your laptop, or point it at a remote server and drive every instance from the browser.

Real Claude Code, always current

No Agents SDK abstraction in the way — it's the actual Claude Code CLI running in each container, so you get the latest features the day they ship.

Your auth, zero config

Existing Claude Code and GitHub credentials are copied into every container automatically — no re-logging in, no tokens to paste.

Everything wired up for you

One `devcontainer up`, plenty of automatic plumbing underneath.

Local folder or Git URL

Copy a folder or clone a repo — either way .git history and your remote come along for the ride.

Browser-based VS Code

Every instance runs its own code-server, proxied same-origin behind your password — no raw ports to remember.

Ready-to-run dev environment

tmux, git identity, and Claude Code aliases are injected into every container — a workflow, not just a shell.

Attention pulses

Containers signal done or waiting back to the dashboard, so you know which tab needs you.

Live dashboard

The full instance list and per-container health stream over WebSockets, reconciled against real Docker state.

Port forwarding

A project's declared forwardPorts/appPort are published automatically — add more anytime.

Runs itself, too

Ship Codebay as a container against the host's own Docker daemon — Docker-outside-of-Docker, no extra install.

One command start

bunx codebay@latest and you're live at localhost:6969 — no config file required.

How it works

From source to a running browser IDE in four steps.

1

Pick a source

A local folder, or paste a Git repo URL.

2

We inject the tooling

code-server, port forwards, and your credentials go into devcontainer.json.

3

devcontainer up

The official CLI builds and starts your container.

4

Open the browser IDE

A unique host port, proxied and password protected.

Every instance gets a mascot

A deterministic 8×8 pixel sprite, picked from a growing catalog — same instance, same avatar, every time.

Get started

No install script, no config file — one command and you're live.

$ bunx codebay@latest
  • Bun ≥ 1.3.14 — Node.js is not supported
  • A running Docker daemon (Docker Desktop, Colima, OrbStack…)
  • macOS or Linux (Windows untested)
